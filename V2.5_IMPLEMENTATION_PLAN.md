# V2.5 — Plan de implementación visual

> Estado: preparado, no iniciado · 23 de julio de 2026  
> Alcance: frontend visual y assets; no cambia datos ni lógica de negocio  
> Fuente visual: `V2.5_ART_DIRECTION.md`

---

## 1. Restricciones

- Preservar cambios ajenos existentes en `SPEC.md`, `data/restaurants_db.json` y handovers.
- No cambiar contratos JSON.
- No introducir APIs, login ni servicios de pago.
- Mantener React + Vite, PWA, Leaflet y funcionamiento offline.
- No añadir librerías de animación ni UI kits.
- No generar imágenes de IA.
- Implementación incremental; cada fase debe compilar y ser desplegable.

---

## 2. Baseline obligatorio

Antes del primer cambio:

1. ejecutar validadores/tests/build existentes;
2. capturar `git status`;
3. levantar cliente con datos reales;
4. capturar viewports 320, 390 y 430;
5. medir build, assets y Lighthouse;
6. guardar matriz de pantallas/estados;
7. identificar fotografías cargadas y precacheadas;
8. comprobar encoding UTF-8 visible.

Entregable: `V2.5_BASELINE.md` con métricas y enlaces a capturas.

## 7. Pruebas por componente

Cada componente debe mostrar:

- default;
- hover cuando aplique;
- pressed;
- keyboard focus;
- disabled;
- loading;
- error;
- contenido largo;
- contenido faltante;
- 320 px;
- 430 px;
- zoom de texto;
- reduced motion;
- contraste;
- offline cuando aplique.

No se acepta una captura del happy path como definición de terminado.

---

## 8. Presupuestos técnicos

- fuentes nuevas: ≤ 180 KB total recomendado;
- textura: ≤ 20 KB;
- hero: objetivo ≤ 250 KB por imagen móvil;
- cero dependencia de animación;
- cero UI kit;
- reservar dimensiones de imagen;
- no aumentar el JS inicial de forma material por diseño;
- Lighthouse móvil: Performance ≥ 85, Accessibility ≥ 95 o no empeorar baseline si este fuera superior;
- no precachear todas las imágenes si excede presupuesto acordado.

---

## 9. Checklist de anti-IA

Antes de cerrar cada fase:

- [ ] No hay copy genérico añadido.
- [ ] No hay emojis funcionales.
- [ ] No hay gradientes ambientales.
- [ ] No hay cards sin razón semántica.
- [ ] No hay tres pills/chips donde bastaba una fila.
- [ ] No hay iconos mezclados.
- [ ] No hay más de una primaria roja.
- [ ] No hay lorem ipsum ni contenido idealizado.
- [ ] Se probó el texto real más largo.
- [ ] Se probó falta de imagen/dato.
- [ ] El diseño contiene una decisión específica del viaje.
- [ ] La pantalla no podría reutilizarse sin cambios en una fintech.
- [ ] Motion funciona desactivado.
- [ ] El acabado táctil se revisó en dispositivo.

---

## 10. Criterio de rollback

Si una migración:

- oculta información crítica;
- rompe navegación;
- reduce contraste;
- incrementa mucho el peso;
- depende de conexión;
- o no supera la captura comparativa,

se conserva el componente anterior y se corrige en aislamiento. No se mezclan medio diseño antiguo y medio nuevo dentro de una misma pantalla publicada.

---

## 11. Entregables por fase

Cada fase entrega:

1. diff acotado;
2. capturas antes/después;
3. matriz de estados;
4. pruebas/build;
5. métricas relevantes;
6. decisiones tomadas;

## 12. Definition of Done V2.5

- Los cinco frames maestros están implementados con contenido real.
- Las vistas restantes comparten fundamentos sin convertirse en clones.
- Las auroras, scanlines, glows y emojis funcionales han desaparecido.
- RouteLine es firma del producto.
- Portada, Hoy y POI concentran el espectáculo.
- Billetes transmite valor sin teatralidad adicional.
- Toda pantalla resuelve estados reales.
- Offline y PWA no retroceden.
- Accesibilidad y rendimiento cumplen presupuesto.
- CSS compartido está centralizado; no quedan nuevos strings grandes de estilos para primitives.
- La revisión ciega no devuelve “plantilla”, “dashboard” o “IA” como impresión dominante.
- El propietario aprueba comparación final antes/después.
